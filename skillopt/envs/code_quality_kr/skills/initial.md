# 코드 작성 스킬

(초기 상태 — 학습된 규칙 없음. 훈련 과정에서 reflection을 통해 채워집니다.)

## 기본 원칙

- 요구사항이 요구한 만큼만 작성합니다. 미래에 필요할지 모를 추상화나 옵션을 미리 만들지 않습니다.
- 한 함수가 너무 길어지면 작은 단위로 나누되, 호출 깊이를 늘리기 위한 분할은 하지 않습니다.
- 변수와 함수 이름은 짧게, 의미는 명확하게. 약어나 일반어(`data`, `info`, `result`) 같은 이름을 피합니다.
- 이미 같은 일을 하는 코드가 있으면 새로 쓰지 않고 호출합니다.
- 주석은 코드만 봐서는 모르는 이유(WHY)만 적습니다. 코드가 무엇을(WHAT) 하는지 다시 풀어 쓰는 주석은 쓰지 않습니다.
- 호출자 입장에서 안 쓰는 매개변수나 분기는 만들지 않습니다.
- 입력이 시스템 경계(외부 API·사용자 입력)일 때만 방어 코드를 둡니다. 내부 호출에는 가드 절을 쌓지 않습니다.
- 기존 파일의 컨벤션을 따릅니다. 같은 모듈 안의 다른 함수가 하는 방식을 보고 맞춥니다.
